01 / INTERFACE

两套接口：谁等结果

普通版把「最大等待时间」写进参数，中断与 DMA 版登记一次就返回。

还是做一下相关编程接口的整理比较好。

最普通的一对，最后一个参数都是最大等待时间：

HAL_UART_Transmit(句柄的指针, 传输数据的地址, 传输数据的大小, 最大等待时间);
HAL_UART_Receive(句柄的指针, 接收数据的地址, 接收数据的大小, 最大等待时间);

最大等待时间的存在使得这种普通的收发编程接口执行时会阻塞代码。

阻塞说的是谁等不到数据、或发不完，函数就一直在里面查标志，直到超时才返回 HAL_TIMEOUT。这段时间里 while(1) 的下一行不会执行。

中断与 DMA 版是另一套：调用只做登记——数据往哪儿放、放多少——立刻返回；搬运由硬件完成，搬完再反过来调你写的回调。所以下文都按「函数 + 回调 + 什么时候进」三样一起记。

02 / RECEIVE

接收：四个函数，两个回调

定长走 RxCplt，变长走 RxEvent。

接收函数对应回调函数触发条件（何时调用）核心特点 / 适用场景
HAL_UART_Receive_IT() HAL_UART_RxCpltCallback() 接收满指定的 Size 字节时 定长 + 中断。适合接收长度固定的报文。
HAL_UART_Receive_DMA() HAL_UART_RxCpltCallback() 接收满指定的 Size 字节时 定长 + DMA。适合高波特率、定长的大数据接收。
HAL_UARTEx_ReceiveToIdle_IT() HAL_UARTEx_RxEventCallback() 收满 Size 或 总线空闲（IDLE） 不定长 + 中断。适合变长协议、AT 指令等。
HAL_UARTEx_ReceiveToIdle_DMA() HAL_UARTEx_RxEventCallback() 收满 Size 或 总线空闲（IDLE） 不定长 + DMA。最常用的高效变长接收方案。
03 / TRANSMIT

发送：两个函数，两个回调

发完调 TxCplt，DMA 搬运过半时多一个 TxHalfCplt。

发送函数对应回调函数触发条件（何时调用）核心特点 / 适用场景
HAL_UART_Transmit_IT() HAL_UART_TxCpltCallback() 全部数据发送完毕时 非阻塞发送。适合发送不频繁、数据量不大的场景。
HAL_UART_Transmit_DMA() HAL_UART_TxCpltCallback()
HAL_UART_TxHalfCpltCallback()		 全部完毕时
发送到一半时		 非阻塞发送。适合大数据量、高波特率发送。半完成回调常用于双缓冲。
04 / ERROR

出错：一条兜底的回调

所有 IT 与 DMA 模式共用这一个错误入口。

无论使用上述哪种 IT（中断）或 DMA 模式，只要在底层通信过程中发生异常（如溢出 Overrun、帧错误、噪声干扰等），HAL 库都会中断当前的正常流程，跳转到这个函数：

回调函数触发条件
HAL_UART_ErrorCallback() 发生任何串口通信错误时（溢出、帧错误、奇偶校验错等）。
05 / RULES

三条结论

记这三句，剩下的查上面的表。

「定长找 Cplt，变长找 Event」

  • 普通的 Receive_IT / Receive_DMA 接收完成，回调是 RxCpltCallback。
  • 带 Ex、带 ToIdle 的那一对（ReceiveToIdle_IT / ReceiveToIdle_DMA），回调是 RxEventCallback。千万别写错，写错永远不会进断点。

「有 Cplt 必有 Error」

凡是通过中断或 DMA 执行的操作，只要出错就会走 HAL_UART_ErrorCallback()。

「上膛」原则

接收要重新上膛对于接收：除了 HAL_UARTEx_ReceiveToIdle_DMA 在某些新型号的 HAL 库中支持循环模式（Circular）外，绝大部分 _IT 和普通 _DMA 接收函数，在进入回调函数后，必须再次调用该接收函数，否则只能接收一次。

06 / CALLBACK

回调到底什么时候进

发送看「发完」，接收看「收满」还是「总线空闲」。

一、发送（Tx）

触发函数触发情况（事件）核心原理
HAL_UART_TxCpltCallback 全部数据发送完毕 最后一个字节的数据从移位寄存器彻底发送到总线上（不仅是从寄存器搬到 FIFO，而是真发完了）。无论用 IT 还是 DMA 模式，都会触发。
HAL_UART_TxHalfCpltCallback 发送到一半 仅限 DMA 模式。当 DMA 搬运了指定缓冲区前一半（50%）的数据时触发。常用于「双缓冲」，在前一半发送时，可以在回调里准备后半部分的数据。

IT 模式 vs DMA 模式IT 模式是每发一个字节进一次中断，发完最后一个才调回调；DMA 模式是发完一半调一次半完成回调，全发完调一次全完成回调。

二、接收（Rx）

接收的回调触发取决于你用的是定长还是不定长函数。

1. 定长接收（Receive_IT / Receive_DMA）

  • 触发回调：HAL_UART_RxCpltCallback
  • 触发情况：接收到的字节数 == 你设定的 Size。
  • 例如你设了 10 字节，对方发了 10 字节，立刻触发。
  • 注意：如果对方发了 15 字节，只触发一次（满 10 字节时）；如果对方只发了 9 字节，永远不会触发。

2. 不定长接收（ReceiveToIdle_IT / ReceiveToIdle_DMA）

  • 触发回调：HAL_UARTEx_RxEventCallback
  • 触发情况（满足任一即可）：
    • 接收满指定长度：收到的字节数达到了你设定的 Size 最大值。
    • 总线发生空闲（IDLE Event）：这是最核心的。当对方发完一帧数据后，总线电平保持高电平超过 1 个字符的传输时间（例如 115200 波特率下大约是 86 微秒），硬件会置位 IDLE 标志。HAL 库检测到这个标志，就会立刻触发回调，并把实际收到的数据长度传给你。

3. 接收过半（仅限 DMA）

  • 触发回调：HAL_UART_RxHalfCpltCallback
  • 触发情况：DMA 搬运的数据量达到了你设定缓冲区的一半。
